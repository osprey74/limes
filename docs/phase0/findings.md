## 取得方法（自動化できる）

- オープンデータページは `https://www.jartic.or.jp/d/opendata/opendata.json`（UTF-8）から描画されている
- `type == "typeD"` の要素に、次の情報が入っている
  - `targetMonth`（対象月）
  - `releaseDay`（公開日）
  - `targetList`（都道府県別 ZIP へのリンク。例：`/202611010000/typeD_hokkaido.zip`）
- ZIP は `https://www.jartic.or.jp/d/opendata` + リンクで取得できる。同意画面や登録は不要
- 群馬県のスラッグは `gumma`
- ZIP 内のファイル名は Shift-JIS（UTF-8 フラグなし）。例：`北海道警_202609_k_2.1.csv`
  - ハンドオフ時点の推測 `hokkaido_...` は誤りだった
- 作成基準日とバージョンの一覧 PDF は `/{リリース}/typeD_kisei_103_UpdateList.pdf` にある
- 日次の更新検知は、`opendata.json` の `releaseDay` とリンクのパスを比較すれば足りる
- 実装：`data-pipeline/limes_pipeline/fetch.py`

## データの鮮度

- 2026-11-01 公開分の内容は「2026年9月末日現在」で、対象月は 2026年09月
- 公開時点で約1か月、月末基準で見ると最大約2か月遅れになる
- ハンドオフ時点の想定「1か月遅れ」より遅い

## 北海道（北海道警_202609_k_2.1.csv）

- 121,497 行、170 項目、文字化けなし、ユニークキーの重複なし
- 一覧 PDF ではバージョンが **K_2.1注**（旧フォーマットからの機械変換）
  - ユニークキーに月をまたいだ継続性がない
  - そのため **ユニークキーを使った差分取り込みはできず、毎月全件を作り直す**
- **中央線（15）が 0 件**
  - 北海道では JARTIC から中央線の情報をまったく得られない
- 代わりに次の規制が取れる
  - 追越しのための右側部分はみ出し通行禁止（17）：1,416 件（すべて線）
  - 車両通行帯（20）：752 件（すべて線、車両通行帯数の記入率 100%）
  - 車両通行帯・進行方向別通行区分・進路変更禁止の組合せ（119）：349 件
  - 中央線の変移（16）：22 件
- 推測：はみ出し禁止（17）は中央線のある道路で指定される規制なので、「中央線あり」の強い証拠になり得る。法令上の位置づけ（道路標示との関係）を確認したうえで判定段5に加えるか判断する
- **道路種別コード（NO.32）と路線名（NO.33）の記入率は 0%**
  - 高速道路・自動車専用道路の判別と道路名の表示は、OSM（`highway`、`name`、`ref`）に頼る
- 最高速度（区間、112）：10,503 件
  - 速度の内訳：30（30.0%）／40（45.0%）／50（22.8%）／60以上（2.2%）
  - 時間帯条件付き 0.0%、車両条件付き 0.1%
  - 車両コード A=1（車両）と A=10（自動車）は全車両扱いなので、条件付きには数えていない
- 最高速度可変（113）：0 件
- 最高速度（区域、114）：116 件（30 が 98.3%、40 が 1.7%）
  - ゾーン30指定コード（NO.139）はすべて空欄
  - 閉じていない面が 1 件ある
- データ更新区分コード（NO.20）はすべて空欄
  - 「廃止」は 0 件で、差分の情報もない
