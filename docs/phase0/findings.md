## 1. 利用規約

出典：[利用規約 PDF](https://www.jartic.or.jp/d/opendata/riyou_kiyaku.pdf)

- 複製・公衆送信・翻案が自由で、商用利用も可能（第2条）。現時点のデータは著作権の対象外とされている
- 条件は次の2点
  - 出典を記載する
  - 加工した場合はその旨を記載し、JARTIC や国が作成したように見せない（第2条(1)イ）
- CC BY 4.0 と互換（第6条(2)）
- したがって、原本 CSV のアーカイブ、加工データの配信、アプリ内での利用はいずれも可能。アプリとデータ配信物には次の表記を入れる
  - 「出典：『交通規制情報』（公益財団法人日本道路交通情報センター）（<https://www.jartic.or.jp/service/opendata/>）を加工して作成」

## 2. 取得方法（自動化できる）

- オープンデータページは `https://www.jartic.or.jp/d/opendata/opendata.json`（UTF-8）から描画されている
- `type == "typeD"` の要素に、次の情報が入っている
  - `targetMonth`（対象月）
  - `releaseDay`（公開日）
  - `targetList`（都道府県別 ZIP へのリンク。例：`/202611010000/typeD_hokkaido.zip`）
- ZIP は `https://www.jartic.or.jp/d/opendata` + リンクで取得できる。同意画面や登録は不要
- 群馬県のスラッグは `gumma`
- ZIP 内のファイル名は Shift-JIS（UTF-8 フラグなし）。例：`北海道警_202609_k_2.1.csv`
- 日次の更新検知は、`releaseDay` とリンクのパスを比較すれば足りる
- 実装：`data-pipeline/limes_pipeline/fetch.py`

## 3. データの鮮度と量

- 2026-11-01 公開分の内容は「2026年9月末日現在」で、対象月は 2026年09月
  - 公開時点で約1か月、月末基準で見ると最大約2か月遅れになる
- 全国合計は ZIP 323 MB、CSV 3.25 GB、439万行
  - 最大は警視庁（ZIP 39 MB、CSV 402 MB）
  - アプリへ配るのは必要な規制種別と判定結果だけなので、配信データはこれよりはるかに小さくなる見込み（実測は Phase 1 で行う）
- 旧フォーマットからの機械変換（「K_2.1注」）かどうかは、CSV の「バージョン」列には出てこない
  - 公開ごとの「作成基準日等データ」PDF（`typeD_kisei_103_UpdateList.pdf`）にのみ記載される
  - 北海道・警視庁を含む 29 都道府県が「注」付き（富山・愛媛は記載なし）。これらはユニークキーに月をまたいだ継続性がないため、**差分ではなく毎月全件を作り直す**

## 4. 全国の傾向（Limes の判定に効くもの）

| 項目 | 結果 | 判定への影響 |
| --- | --- | --- |
| 中央線（15） | 47 都道府県中 22 が 0 件。最多の群馬でも 1,045 件 | **JARTIC の中央線は全国的にほぼ使えない** |
| はみ出し禁止（17） | 全都道府県にある（愛知 11,976 件、北海道 1,416 件など） | 中央線の主な証拠になる（第5節） |
| 車両通行帯（20） | 0〜9,804 件と都道府県差が大きい | 補助的な証拠 |
| 最高速度（区間、112） | 全都道府県にあり、計 192,106 件 | 判定段1の主役 |
| 最高速度可変（113） | 石川 7、大阪 36、奈良 4 のみ | ほぼ考慮不要 |
| 道路種別コード（NO.32） | 記入があるのは宮城・富山・兵庫・高知・大分（95〜100%）と大阪（25%）だけ | 高速・自専道の判別は OSM に頼る |
| 路線名（NO.33） | 全都道府県で 0% | 道路名は OSM（`name`/`ref`）から取る |

条件付きの規制（最高速度、区間 112）：

- 時間帯条件付きと車両条件付きは、どの都道府県でも 0〜3%
  - 「通年」「終日」「全車両」の書き方が都道府県ごとに違う。ゼロ埋め、`0101`〜`1231`、時刻 `0`〜`0` など
  - これらを条件なしと判定するように実装した（`jartic.py`）
- 愛知は曜日コードが全件 `9` で、これは仕様書の共通コード表にない値
- 長野（98%）・岡山（92%）は、対象車両が「その他」だけで、規制条件の欄が空欄
  - 対象車両をデータから判断できないため、アプリでは**安全側に倒して全車両に適用**とする案を推奨する

## 5. はみ出し禁止（17）と中央線の関係（法令上の位置づけ）

一次資料：警察庁交通局長通達「『交通規制基準』の改正について」（平成29年4月24日、警察庁丙規発第6号）別添「交通規制基準」第10 中央線（<https://www.npa.go.jp/laws/notification/koutuu/kisei/kisei20170424.pdf>）

- 留意事項1：「道路の両側に追越しのための右側部分はみ出し通行禁止の道路標示は、中央線を表示する道路標示を兼ねる。」
- 留意事項4：「道路管理者が設置した区画線『車道中央線(101)』は、道路標示『中央線(205)』とみなされる。」
- 中央線の設置対象道路（規制実施基準）
  1. 舗装幅員 6.5 m 以上
  2. 5.5 m 以上 6.5 m 未満で、日交通量がおおむね 1,000 台以上などの条件を満たすもの
  3. 5.5 m 未満で必要があるもの
  - ハンドオフ時点の「目安は 5.5 m 以上」は不正確で、原則は **6.5 m 以上** だった
- この基準は平成29年版。以降の改正の有無は未確認

JARTIC 上の扱い：

- 片側・両側コード（NO.136）は 1＝無し、2＝片側、3＝両側。片側の規制はコードの登録が必須
- 全国の 17 は 40,118 件。内訳は次のとおりで、両側（3）と空欄（＝片側ではない）を合わせると 97.8% になる
  - 3（両側）：29,433 件
  - 空欄：9,798 件
  - 2（片側）：684 件
  - 1（無し）：203 件
- **結論（案）：17 の線規制のうち、片側・両側コードが 3 または空欄のものを「中央線あり」の証拠（信頼度 high）として判定段5に加える**
  - 2（片側）と 1（無し）は単独では証拠にしない。1 が線規制で何を意味するかは仕様書から読み取れず、未確認
  - 道路標識だけで指定されているはみ出し禁止は、データ上で区別できない。この点は残るリスクとして扱う

## 6. 札幌試験区域（北区、約 2.7 km 四方）の判定試算

[mesh-sapporo-kita24.md](mesh-sapporo-kita24.md) より。OSM 728 way・260 km を判定段1〜8に当てはめた結果：

| 判定段 | 延長の割合 |
| --- | ---: |
| 1 規制速度（JARTIC 112/114） | 39.9% |
| 2 高速自動車国道 | 0.1% |
| 4 中央分離帯 | 1.9% |
| 5 中央線・通行帯（JARTIC 20 または OSM `lanes`） | 14.6% |
| 7 生活道路（30） | 41.8% |
| 8 不明 | 1.8% |

所見：

- 延長の約4割は JARTIC の規制速度で決まり、照合誤りの指標になる OSM `maxspeed` との不一致は 0 件だった
- この区域にはみ出し禁止（17）は 0 件
- 30（low）の 97.7 km のうち 18.7 km は、地理院の幅員区分が 5.5〜13 m
  - 中央線を見落としている（本当は 60）候補であり、最大のリスク
  - 地理院の区分は 5.5〜13 m と幅が広く、基準の 6.5 m と境界が一致しないため、幅員だけでは決められない（決定事項 8 と整合）
- 不明（4.7 km）は、`highway=tertiary` で証拠がない道路。幹線に近い道路で数値を出せない区間が残る
